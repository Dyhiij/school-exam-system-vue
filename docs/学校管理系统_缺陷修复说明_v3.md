## 二、数据库变更（新增 2 张表，共 7 张）

```sql
-- 试卷-题目关联表（多对多，修复"组卷无题"）
CREATE TABLE exam_paper_question (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  paper_id BIGINT NOT NULL,
  question_id BIGINT NOT NULL,
  UNIQUE KEY uk_paper_question (paper_id, question_id)
);

-- 作答明细表（每题答案+得分；简答题 correct_flag=0 待人工阅卷）
CREATE TABLE exam_answer (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  batch_id BIGINT NOT NULL,          -- 考试批次
  user_id BIGINT NOT NULL,           -- 考生
  question_id BIGINT NOT NULL,       -- 题目
  question_type TINYINT,             -- 题型(1单选2多选3判断4填空5简答)
  user_answer TEXT,                  -- 考生答案
  correct_flag TINYINT DEFAULT 0,    -- 1对0错；简答0=待阅
  got_score DECIMAL(5,1) DEFAULT 0,  -- 得分
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_batch_user_question (batch_id, user_id, question_id)
);
```

> 注意：`exam_score` 表(原第5张)现在真正被写入；状态字段语义：0=未交 1=已交卷(简答待阅) 2=已阅卷。

## 四、（v3 新增）防重复交卷 + 交卷后切屏警告修复

> 触发：软件测试手工执行 TC-04「防重复交卷」时实测发现（2026-09-09）。测试人邓钰浩。

### 4.1 缺陷现象（实测证据）
1. **重复交卷未被拒绝**：首次交卷（60 分）后再次进入考试并提交，系统接受并**覆盖**成绩（数据库成绩行数仍为 1，但分数被第二次答卷覆盖、提交时间刷新）。后端实现为"覆盖更新"而非"拒绝"，前端仍弹"🎉 交卷成功！"，考生无法察觉异常。
   - **风险**：考生可反复"交卷→看分→改答案→再交"刷分；若教师已阅卷（status=2），重复交卷会把状态打回待阅卷。
2. **交卷成功后切屏仍警告**：交卷成功弹窗期间（未点"返回首页"）切屏，前端仍触发"检测到切屏"警告。原因：切屏监听无"考试已结束"判断，交卷后监听未失效。

### 4.2 修复方案（三层防线）
| 层 | 修复 | 涉及文件 |
|---|---|---|
| ① 后端兜底（核心） | `submitExam()` 开头新增已交卷检查：`exam_score` 已存在 `batch_id+user_id` 记录 → 直接返回 `code=403 "您已提交过答卷，不能重复交卷"`，**不再覆盖**（检查在写任何数据之前，拒绝无副作用） | `ExamController.java` |
| ② 前端入口拦截（体验） | 进入考试房间加载试卷后，调 `my-scores` 查当前用户是否已交本批次 → 已交则弹窗提示"不能重复进入考试"并返回列表，不再展示试卷 | `ExamRoom.vue`（`checkAlreadySubmitted()`） |
| ③ 前端交卷收尾 | 交卷成功 / 收到 403 时置 `examFinished=true`：切屏监听、复制粘贴禁止、倒计时立即失效，不再对已结束的考试报警 | `ExamRoom.vue`（`examFinished` 标志） |

### 4.3 回归验证（实测通过）
- 重复交卷请求 → 返回 `code=403`，msg 明确提示；数据库成绩行数仍 1、分数/时间戳**未被改动**（无副作用）。
- 首次交卷流程不受影响：交卷 → 客观题得分落库 → 状态 1（简答待阅）。
- 前端 build 通过（vite build 零错误）。

### 4.4 测试报告口径（面试/报告用）
> "TC-04 防重复交卷实测发现：系统允许重复交卷并覆盖成绩，存在刷分风险（缺陷）。推动小组修复：后端改为已交卷即拒绝（403）、前端增加进入拦截与交卷后监听失效。回归验证：重复交卷被拒且数据无副作用，缺陷关闭。"
